# 交接：《易境 · 爻爻》的经验（给接手的新对话看）

> 写给在用户 Windows 电脑上新开的 Claude 对话。用户要做**新游戏**，不想把以前讨论过的东西再讲一遍。
> 这份文档把做《易境 · 爻爻》时定下的规矩、架构、踩过的坑和改法都写下来。**先通读，再动手**；文档里说过的事不用再问用户。
> 源码在本仓库 `claude/q-edition` 分支的 `yijing-q/` 目录，遇到不清楚的地方直接读代码（文中给了文件位置）。

## 0. 和用户合作的规矩（最重要）

用户的长期偏好：
- **除非用户特别要求，一律用中文回答。**
- **不要立刻动手。** 用户没说"做"之前，先头脑风暴，给方向和取舍，等用户拍板。
- **不迎合，也不为反驳而反驳。** 没疑问就继续做，有疑问就直接问。用户说得不对就说不对，并讲理由。
- 回答要短、说人话。用户经常在手机上看，长篇大论和术语会被嫌弃。
- 用户给的设计意见非常具体（"狐狸像小狗""龙画成了长虫"），要按字面认真改，改完自己截图看一遍再交。

仓库规矩：
- 不修改别人（Codex）做的原版游戏和 `main` 分支。新东西放独立目录、独立分支。
- 没被要求就不开 PR。
- 提交信息不写模型名。
- **考据必须准确**：引古籍要注明出处、和原文一致；游戏里自创的玩法明确标"原创"；后世才有的说法要标出来（例如"错卦/综卦"作为名称通行于明代来知德之后，标"后世之说/宋人之说"），不冒充古籍。拿不准的出处要写"建议核对"。

交付习惯：
- 文件发给用户时注意大小。用户那边上传、下载很费劲：视频压到 20MB 以内（720p），给 zip 前确认没多余的东西。
- 用户要可以直接上传的东西（zip、封面、视频），做完就给，不要只说"在某某路径"。

## 1. 项目概况

- 3D 平台跳跃 + 解谜，主题是周易八卦。主角是四个 Q 弹果冻小团子（爻爻、糯糯、麟麟、鲤鲤）。
- 做到四境：坎 → 离 → 水火既济 → 火水未济（整关在水下）。第五境「乾」做了试玩段，**暂停中**，用户说小龙"画成了长虫"，要重做造型。
- 发布渠道：**小红书小工具**（zip 包）和单文件离线网页。用户在小红书发宣传视频、封面和更新说明。
- 技术栈：原生 JS（ES 模块）+ Three.js r179（放在 `vendor/`，不走 npm），esbuild 打包，Playwright 自动测试，ffmpeg 合成视频。**不用任何游戏引擎和框架**，所有模型都是代码里拼出来的。

常用命令（在 `yijing-q/` 下；Windows 也一样能用）：
```
npm install
npm start                              # 本地服务器 http://127.0.0.1:8520
npm run build                          # 单文件离线版 dist/易境-爻爻.html
npm run verify                         # 全套自动验证（先 build）
set VERSION=1.3.3&& node tools/build-minitool.cjs   # 小红书小工具包 → release/易境爻爻-小工具-<版本>.zip
node tools/test-minitool.cjs           # 小工具包自测（手机视口、拦截网络）
node tools/test-smooth.cjs             # 顺滑度回归测试
node tools/verify-stuck.cjs            # 防卡死测试
```
Windows 上第一次用 Playwright 要 `npx playwright install chromium`；录视频要装 ffmpeg。

目录：
```

src/physics.js     平台物理：固定步长、碰撞、二段跳、游水、震、防卡死、安全落脚点
```

## 2. 镜头与视角（踩坑最多的地方）

镜头代码在 `src/main.js` 的 `render()` 里：第三人称环绕，参数 `cam = {yaw, pitch, dist, focus}`，都朝 target 值缓动。拖动屏幕转 yaw/pitch，pitch 限制在 0.12～1.25。

### 2.1 往后退时画面一顿一顿（已修）
- **错误做法**：镜头碰撞用"从角色往镜头打射线，碰到东西就把镜头拉到碰撞点前面"。第四境往后退时，矮墙一会儿挡、一会儿不挡，镜头每帧前后跳一截。
- **改法**：
  - 只判断**镜头所在的那个点**是不是钻进了"高墙"（关卡里标了 `camBlock` 的碰撞体）。
  - 钻进去了，就沿视线二分查找，找到最远的不在墙里的位置。
  - 结果再平滑：往里收要快（系数 14），往外放要慢（系数 3）。
  - **矮墙不管**，镜头直接从上面越过去。
- 原则：**镜头位置绝不能每帧突变**，任何修正都要连续、平滑。

### 2.2 镜头前视（look-ahead）撞墙跳一下（已修）
- 镜头焦点会往角色速度方向前探一点（`camLead`）。角色撞墙急停，速度瞬间归零，焦点就跳回来。
- 改法：`camLead` 本身也做指数平滑。

### 2.3 镜头被东西挡住，看不见角色（已修，用户反复提过）
- 挪物体、调镜头只能治标，最后的通用方案在 `src/occlude.js`：
  - 给场景里所有普通材质注入一段片元着色器代码（`onBeforeCompile`）。
  - **在"镜头 → 角色"连线附近的片元**，和**离镜头很近的片元**，用 4×4 Bayer 网点 `discard` 掉，看起来就像半透明。
  - **只处理比角色脚面高的部分**，所以地面不会被挖出洞。
  - 角色自己的材质排除在外。
  - 材质本来就有 `onBeforeCompile` 的（水草、鱼、焦散），要接在它后面改，并且改 `customProgramCacheKey`，否则着色器缓存会串。
- 每关加载完调一次 `patchScene(scene, mascot.root)`。新加的材质要在 patch 之前建好，否则不生效。
- 网点会把挡在中间的伙伴（小狐狸）也变透明，可以接受。
- 新游戏**一开始就把这套机制装上**，不要等用户抱怨。

### 2.4 关卡里的镜头限制
- 水下关用 `level.camMaxY(p)` 限制镜头高度：不让镜头穿出水面，暗洞里不穿出洞顶。
- 关卡出生时设 `L.camYaw`，让镜头朝向前进方向。

### 2.5 重要物件被场景挡住（已修）
- 第四境暗洞的壁画被"光苔"和一块石头挡住，用户截图问"为啥放个东西给它挡住"。
- 教训：**放置关键物件（壁画、碑、机关）后，要从玩家实际会站的位置截图检查**，不能只看俯视图。

### 2.6 横屏模式（小红书锁竖屏）
- 小红书小工具强制竖屏。要横屏玩，就把整个页面旋转 90°（CSS）。
- 旋转后，摇杆和拖动镜头的触摸坐标要换算（`toLocal`：横屏时 `{x:dy, y:-dx}`），否则方向全反。
- 弹窗单独旋转、居中。

### 2.7 标题页的构图
- 标题页用 `camera.setViewOffset` 把角色挪到画面空白处：宽屏往左挪、窄屏往上挪，不要被标题卡片盖住。

## 3. 卡顿与流畅度（用户第一个大抱怨）

用户原话"一卡一卡的，尤其是一开始的时候"。根因和改法：
1. **没有渲染插值**：物理按固定步长每秒 120 步，画面刷新率 60/90/120 不等，角色位置就一顿一顿的。
   - 改法：渲染时在两步物理之间按比例插值（`prevP` + `interp()`）。
2. **纯画面的东西放在物理步里算**：鱼群、气泡、水母原来每秒算 120 次，还每帧 new 临时对象。
   - 改法：全部挪到关卡的 `frame(dt, t, p)` 钩子里，每帧只算一次；不在热循环里分配对象。
   - 效果：每步耗时 0.43ms → 0.06ms。
3. **刚进关卡**：边走边编译着色器。
   - 改法：进关时 `renderer.compile(scene, camera)` 一次编好。
4. **自动降画质误触发**：进关头几秒的编译卡顿被当成机器太慢，自动降了画质，结果又全部重编一遍，更卡。
   - 改法：进关后有 4 秒宽限期（`perf.grace`）；单帧超过 0.25 秒的停顿不计入。
5. 回归测试是 `tools/test-smooth.cjs`：模拟抖动的 60Hz 和稳定的 90/120Hz 刷新，测相邻帧角色在屏幕上位移的抖动。**新游戏也要有。**

性能红线（手机上要跑）：
- **每帧绘制调用（draw call）≤ 100。**
  - 静态装饰用 `world.bake()` 合并成少数网格。
  - 大量重复物体用 InstancedMesh（鱼群、贝壳、海葵触手）。
  - 卦画合成单个网格（`kit.hexBars`）。
  - 按区域隐藏看不见的东西（`seen(iz)`），只显示当前区域和相邻区域。
- 像素预算：像素比上限 1.5，总像素约 200 万；掉帧（平均帧时间 > 1/22 秒）就降一档（像素比降到 1、再关阴影）。
- 后台暂停：切到后台就停声音、丢掉时间差，回来不补算。
- WebGL 上下文丢失要处理，不能白屏。

## 4. 物理与"卡死"

- 物理固定步长 1/120 秒，结果和帧率无关，测试才稳定。
- **卡死 bug**（玩家录视频反馈：第一境卦门旁的松树）：
  - 原因：从上方落到细圆柱（树干、竹子、石灯）边上，落点在"站不上去、但已进入挡人范围"的那一圈里。之后往哪个方向走都被判定为撞墙，永远走不出来。
  - 改法：每步物理开始先 `pushOut()`，角色和障碍物重叠时推到最近的边外面。
  - 测试 `tools/verify-stuck.cjs`：把所有细障碍物从四个方向各落一次，必须都能走开。去掉修复时，这个测试能测出 7 处以上卡点。
- **🚩 复位（T 键）**：
  - 记录最近 12 个站稳过的点（`p.spots`），复位到离当前位置至少 1.5 米、本身不挡人的那一个。
  - 进度（爻玉、机关）保留。
  - 和"↺ 整关重来"分开。
- **卡住自动提示**：推着方向约 2.6 秒几乎没挪动，就弹提示，🚩 按钮闪一闪；20 秒内不重复提示。
- 用户的思路是"像赛车游戏那样保留进度复位"。**新游戏默认就带上复位键。**

## 5. 界面与提示

- 每到一个区域会弹一段说明（toast）。用户要求**必须能关掉**：右边有 ×，点提示框本身或按 Esc 也能关。别做成只能等它自己消失。
- 目标提示常驻左下；横屏时只显示一行，点一下展开。
- 手机上顶栏按钮放不下就换第二行；测试会检查每个按钮都在屏幕内。
- 图鉴（codex）：每张卡有拼音、白话、要点、原文和出处，以及"在游戏里"的对应；按进度解锁，存档。

## 6. 美术：用户的口味和改过的造型

整体风格：Q 弹、软糖 / 果冻质感、明亮卡通配色。材质主要用 `MeshPhysicalMaterial`（clearcoat、sheen、emissive 微亮）和 Toon 材质。

**小狐狸的迭代**（用户说"不太可爱"，前后改了好几轮）：
- 第一版像**小狗**。改成尖嘴、大耳、蓬松大尾巴。
- 尾巴做成一节节球，像**毛毛虫**。改成旋转体（Lathe）一整根。
- 耳朵像**独角兽角**、身上像有刺。改成水滴形耳朵，而且要埋进头里，别悬空、别有棱角。
- 最终方向：Q 版比例（大圆头、小鼓包嘴、大眼睛加两个高光、腮红、蓬松大尾巴），奶白软糖。还做了"红绳结""冰糖"两种备选，用户还没选。
- 动作：用骨骼蒙皮（身子、头、耳、眼、四爪、两节尾巴）做加速拉长、急停压扁、转弯内倾、眨眼、东张西望、偶尔翻跟头。
- 用户明确说过：**伙伴不要带路**（不要做成引导 NPC），只是陪着、有小性子。

**第五境小龙**被说"画成了长虫"：一串由粗到细的珠子身体 + 大圆头，读起来就是虫。重做时要有明确的龙特征（龙头轮廓、角、鬃、爪、鳍、身体比例），不要只是一串球。

**鱼**：做成卡通鱼（纺锤身、叉尾、大眼、背深腹浅、侧身闪银光），每群鱼一次绘制。

**教训**：
- 代码拼模型很容易拼出"奇怪的东西"。每次改完都要**从游戏视角截图**（不只是 T-pose 特写），确认读起来是想要的东西。
- 用户会拿真实的可爱参考来比，差一点都看得出来。

## 7. 玩法设计：用户在意的点

- **玩法要有新意，不要单调重复。** 用户否掉过"画爻造桥"（没看懂）、"画阴爻"（不符合乾卦全阳的卦义）、"单纯画画"（太单调）。
- 用户认可的方向：卦义当骨架（例如乾卦以"六龙"为主线），穿插有画面感的互动（云从龙、同声相应：小龙唱、你在编磬上照着敲）。
- 玩法和卦义要对得上，但对应关系要标"原创"。
- 关卡要"丰富"：用户说过"关卡丰富程度还得再加"。最后第四境加了大鳐鱼摆渡、震碎石头、海龟、灯座谜题和壁画、海葵蹦床、螃蟹、章鱼、鲸、12 枚贝壳收集。可收集物配一个奖励（小狐狸的珊瑚发卡）很受欢迎。
- 每关三颗星：通关、收集全、不落水。另有挑战模式（限时）。

## 8. 测试方法（这套很好用，新游戏照搬）

- 游戏暴露测试接口 `window.__Q`：`manual=true` 后用 `step(秒, {move, jump, up})` 确定性推进，加上 `teleport`、`interact`、`start(关卡号)` 等。
- `tools/verify*.cjs`：**不瞬移**，按航点真实走、跳、游，打通整关，同时截图。航点格式见 `tools/route.cjs` 和 `tools/verify-weiji.cjs`。
- 测试里踩过的坑：
  - `__Q.player` 要在 `start()` **之后**再取，否则拿到的是旧对象，测试会误报失败。
  - 检查 toast 时看 class，别看 opacity：它在过渡动画中间，值不确定。
- 云端机器没有显卡（SwiftShader），帧率和手感测不准。**真实手感一定要在手机上试**。

## 9. 小红书小工具打包规范

见 `tools/build-minitool.cjs` 开头的注释，脚本里有静态自查，违规会直接报错。要点：
- zip 根目录放 `index.html`。
- **只能用经典脚本**：不能用 ES 模块、内联脚本、行内事件（`onclick=`）、`javascript:` 链接。
- **不能联网**：不能有任何外部链接或资源，字体、模型、贴图都要打进包里。
- JS 转译到 **ES2017 / Chrome 61**。踩过的坑：`Object.fromEntries`、`Array.prototype.flatMap` 在 Chrome 61 上没有，已改掉。（Three.js 里的 `Ray.at` 是它自己的方法，不受影响。）
- CSS 要有 Chrome 61 基线层（`compat-pre.css` / `compat-post.css`）。Flex `gap` 不生效时改用 margin。
- 存档用容器的 `xhs.miniTool.getStorage/setStorage`（客户端 9.46 以上）；`localStorage` 只做兜底。
- Three.js r179 需要 **WebGL 2**。不支持时显示说明文字，不能白屏。
- 安全区用"容器注入的变量 + `env()`"组合。
- 每次发包都升版本号（`VERSION` 环境变量），release 里保留历史包。

## 10. 宣传素材流程

- **攻略 / 更新视频**：`tools/rec/record.cjs`（前三境）和 `tools/rec/record-weiji.cjs`（第四境）。
  - 原理：虚拟时钟逐帧推进游戏，脚本按航点真实操作角色，每帧截图；声音事件记成日志，再用游戏自己的合成器离线渲染音轨（`tools/rec/finish.cjs`），最后 ffmpeg 合成。
  - 规格：1280×720，界面放大 1.5 倍（手机上看得清），30fps，中文字幕说清"怎么玩"，右下角显示按键。
  - 2 分钟成片在云端要录 40 分钟左右（没有显卡）。在有显卡的电脑上会快很多。
  - 发给用户前再压一个 720p、20MB 以内的版本。
- **封面**：3:4，1440×1920。
  - 做法：在游戏里摆好镜头渲染场景（隐藏 HUD），再用 HTML 叠设计过的标题，Playwright 截图。
  - 字体用站酷快乐体（ZCOOL KuaiLe）做标题，思源黑体做正文；emoji 用 Noto Color Emoji。
  - 用户要的是"游戏主题封面"：游戏画面加好看的排版，不是普通截图。
- **更新说明**：用户发在小红书，要**小红书口吻**：emoji 分段、短句、带话题标签，直接贴在聊天里给，不要给 md 文件。

## 11. 给新游戏的建议（用户打算用 GPT + Blender 做美术）
